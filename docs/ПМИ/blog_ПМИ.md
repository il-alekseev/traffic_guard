# Программа и методики испытаний сервиса **blog**

## 1. Введение

Сервис **blog** — микросервис на Go, предоставляющий REST API для записи и получения бизнес-логов. Основные функции:
- Отдача информации о версии и healthcheck;
- Приём логов (POST `/api/v1/add`);
- Получение логов с фильтрацией и пагинацией (GET `/api/v1/logs`);
- Swagger UI доступен по `/swagger/*any`.

Сервис использует PostgreSQL (GORM) для хранения данных. Токены Bearer в заголовке авторизации используются для определения роли (SA, CA и др.).

## 2. Короткое описание API (обнаружено в исходниках)

- `GET /api/v1/healthcheck` — проверка состояния (health).
- `GET /api/v1/version` — возвращает версию сервиса. Пример ответа: `{"message":"1.0.0"}`.
- `POST /api/v1/add` — добавление записи (JSON body — BusinessLog).
- `GET /api/v1/logs` — получение логов с параметрами фильтрации и пагинацией. Защищён Bearer токеном и middleware-валидацией.

Тело для `POST /api/v1/add` (структура `BusinessLog`):
```json
{
  "event_type": "CREATE|UPDATE|DELETE",
  "entity": "user|context|...",
  "user_name": "имя пользователя",
  "user_role": "SA|CA",
  "context": "текст контекста",
  "entity_id": "идентификатор сущности",
  "old_value": null,
  "new_value": {"...":"..."},
  "description": "текст"
}
```

Параметры для `GET /api/v1/logs` (структура `FilterLogs`):
- `page` (int)
- `limit` (int)
- `role` (string)
- `context_id` (string)
- `search` (string)

## 7. Методика проведения испытаний

### 7.1 Подготовка тестового окружения
1. Клонировать/распаковать проект.
2. Установить переменные окружения (пример `.env`):
```
BLOG_APP_NAME=blog
BLOG_APP_VERSION=1.0.0
BLOG_HTTP_HOST=0.0.0.0
BLOG_HTTP_PORT=7000
BLOG_PG_HOST=postgres
BLOG_PG_PORT=5432
BLOG_PG_USER=blog
BLOG_PG_PASSWORD=blogpassword
BLOG_PG_DBNAME=blog
BLOG_PG_SSLMODE=disable
BLOG_PG_POOL_MAX=10
BLOG_SWAGGER_HOST=127.0.0.1
```
3. Запустить зависимости и сервис (в корне `build/docker-compose.yaml`):
```bash
docker-compose -f build/docker-compose.yaml up -d
# или при локальном запуске (если установлен Go):
make build && ./blog --config ./config/config.yaml
```

### 7.2 Запуск тестов вручную (примеры curl)

- Healthcheck:
```bash
curl -v http://localhost:7000/api/v1/healthcheck
```

- Version:
```bash
curl -v http://localhost:7000/api/v1/version
```

- Add record (пример):
```bash
curl -X POST http://localhost:7000/api/v1/add \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"event_type":"CREATE","entity":"user","user_name":"tester","user_role":"SA","description":"test entry"}'
```

- Get logs (пример фильтрации и пагинации):
```bash
curl -v "http://localhost:7000/api/v1/logs?page=1&limit=10&role=SA&search=test" \
  -H "Authorization: Bearer $TOKEN"
```

## 8. Мониторинг и логирование во время тестирования

- Собирать логи контейнеров (`docker logs -f`) и смотреть сообщения об ошибках.
- Анализировать метрики PostgreSQL (пул соединений, время выполнения запросов).
- Собирать метрики CPU/Memory контейнеров (docker stats, Prometheus если есть).
